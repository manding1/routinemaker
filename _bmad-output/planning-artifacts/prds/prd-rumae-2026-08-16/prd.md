# PRD: MANDING
*Working title — confirm.*

## 0. Document Purpose

이 PRD는 MANDING(개인용 습관/루틴 형성 웹앱)의 제작자 본인을 위한 기획 기준 문서다. 용어는 §3 Glossary에 정의된 대로 일관되게 쓰이며, 기능은 §4에서 FR(전역 번호)로 묶여 있다. 이 문서는 `handoff-prompt_1.md`(원 기획서)와 `DESIGN-apple.md`(디자인 토큰 참고자료), 그리고 discovery 대화에서 나온 구조 변경 사항을 통합한 최신본이다. 시각/인터랙션 레벨의 세부(그래프 스티커북 목업, 포도알 젤리 질감 등)는 `addendum.md`에 있으며, 이후 UX 스펙 단계에서 이어받는다.

## 1. Vision

MANDING은 의지력이 아니라 인지 설계로 하루를 굴러가게 만드는 1인용 도구다. 큰 목표를 퍼센트로 들이밀지 않고, 언제나 "지금 밟을 돌 하나"만 보여준다. 사용자는 여러 개의 포도송이(관심 주제)를 동시에 조금씩 키워나가고, 한 포도송이가 충분히 반복되면 더 이상 결정을 요구하지 않는 자동 루틴으로 "졸업"한다. 앱의 유일한 비교축은 최종 목표가 아니라 어제의 나이며, 행동 하나하나가 그 자체로 축하받는다. 앱은 다음에 뭘 하라고 묻지 않는다 — 사용자가 준비됐을 때 스스로 채워 넣을 뿐이다.

### Design Principles

원 기획서(`handoff-prompt_1.md` §2)의 절대 원칙을 그대로 옮긴다. 이 PRD의 모든 FR은 아래 원칙을 어기지 않아야 한다.

1. **최종 목표를 진도율(%)로 보여주지 않는다.** 분모가 최종 목표인 순간 좌절이 생긴다.
2. **미리 계획을 다 쪼개게 시키지 않는다.** 포도송이는 이름만으로 생성되고, 세부 걸음은 그때그때 채워진다.
3. **항상 '바로 다음 딱 하나'만 존재하게 한다.** 포도송이당 현재 걸음은 언제나 하나다(FR-2).
4. **다음 단계는 방금 하나를 끝낸 직후가 가장 가볍다.** *(적용 방식 변경: discovery 중 명시적 "다음은?" 질문 자체를 없애기로 했다 — FR-5 참조. 완료 직후 축하 + 조용한 대기로 같은 타이밍 원칙을 유지하되, 명시적으로 묻지는 않는다.)*
5. **실패는 혼내지 않고 "더 작게 쪼개라는 신호"로 다룬다.** *(적용 방식 변경: 시스템이 "너무 크다"고 먼저 단정하지 않는다. 중립적인 [수정]을 열어두고, 사용자가 스스로 판단해 더 작게 쓰면 그게 이 원칙의 실현이다 — FR-6 참조.)*
6. **비교 대상은 최종 목표가 아니라 '어제의 나'다.** (FR-7, FR-9)
7. **감정이 아니라 행동을 기록한다.** *(긴장 관계 있음: §4.4 FR-18의 감사일기/확언 섹션 참조.)*

## 2. Target User

### 2.1 Jobs To Be Done

- 아침에 일어나는 것 자체가 힘든 사람이, 첫 동작부터 부담 없이 시작하고 싶다. *(전용 온보딩 기능은 없음 — 사용자가 원하는 첫 포도송이/걸음을 직접 정의해서 채운다.)*
- 하고 싶은 게 많고 목표가 높은 사람이, 전체 계획을 미리 짜는 부담 없이 "바로 다음 한 걸음"만 생각하고 싶다.
- 실패했을 때 혼나지 않고, 그 신호를 "더 작게 쪼개라"는 뜻으로 받아들이고 싶다.
- 자주 반복하게 된 행동은 더 이상 매번 결정하지 않고 자동으로 넘어가길 원한다(에너지 절약).
- 하루를 마감하며 잘한 점과 감사한 점을 짧게 남기고 싶다.
- 이것은 제작자 본인만을 위한 도구다 — "나를 위해 만든다"는 프레이밍 자체가 유효한 JTBD.

### 2.2 Non-Users (v1)

- 여러 사용자가 함께 쓰는 팀/가족용 시나리오 — 로그인·계정·공유 개념 없음.
- 알림/리마인더로 재촉받고 싶은 사용자 — MANDING은 앱을 여는 순간에만 반응하는 pull 방식이며, 다음 행동을 묻지도 않는다.

### 2.3 Key User Journeys

- **UJ-1. 지수, 첫 포도알을 심다.**
  - **Persona + context:** 지수, 아침형이지만 기상 자체가 힘들고 목표는 높지만 작은 성취부터 맛보고 싶어 함.
  - **Entry state:** 로그인 없음, 앱을 처음 설치해 염. 포도송이가 아직 하나도 없는 빈 상태.
  - **Path:** ① 빈 화면에 [새로운 포도송이 추가] 버튼만 보임. 지수가 "아침 시동"이라는 포도송이를 만들고, 첫 걸음으로 "두 발 바닥에 대기"를 직접 입력. ② 포도알을 탭해 완료 → 즉시 "어제보다 나은 오늘입니다!" 축하가 뜨고, 현재 걸음 칸은 조용히 비워져 다음 입력을 기다림(질문 문구 없음). ③ 지수가 내킬 때 "물 한 잔 마시기"를 입력 → 새 현재 걸음. ④ [새로운 포도송이 추가]로 "달리기 1.5km" 포도송이를 시작, 완료 시 포도알 탭 → 축하. 같은 날 그 포도송이를 또 채우려 해도 오늘 치는 이미 받았으므로 알이 늘지 않고, 담담한 안내만 짧게 뜬다. ⑤ "책상 앞 공부 시작"이 부담스러워 ⋯ 메뉴에서 [수정] → "의자에 앉기"로 교체. ⑥ 오늘 총 포도알 수가 어제보다 많아지는 순간 별도 축하가 한 번 더 뜬다.
  - **Climax:** 여러 포도송이에서 포도알을 탭할 때마다 축하가 쌓이며, 숫자 비교나 재촉 없이도 "오늘 뭔가 하고 있다"는 감각이 누적됨.
  - **Resolution:** "오늘 마무리하기"를 선택 → 오늘의 리뷰(잘한점/개선할 점/감사일기/확언)를 작성하고 하루 종료.
  - **Edge case:** 특정 포도송이를 오늘 더 하고 싶지 않으면 그냥 빈 칸으로 둔다 — 앱은 재촉하지 않으며, 별도의 종료 액션이 필요 없다.

- **UJ-2. 달리기 포도송이의 졸업, 그리고 이어지는 아침.**
  - **Persona + context:** 지수, 몇 주 뒤(하루 1알 제한 때문에 최소 15일이 걸림). "달리기 1.5km" 포도송이가 15/15로 가득 참.
  - **Entry state:** 다음날 앱을 다시 염.
  - **Path:** ① 포도송이가 가득 찬 순간 자동으로 루틴 체크리스트 항목으로 전환됨을 알림. ② 앱을 열면 "달리기 1.5km"가 루틴 체크리스트에 나타나고 다음 미완료 항목이 강조 표시됨. ③ 나머지 포도송이("독서" 등)는 그대로 성장 중인 상태(현재 걸음 카드)로 계속 진행.
  - **Climax:** 체크리스트 항목을 체크할 때는 포도알 적립도, 축하 문구도 없이 담담하게 완료 표시된다 — 더 이상 결정을 요구하지 않는다는 것 자체가 보상.
  - **Resolution:** 그날도 동일하게 "오늘 마무리하기" → 오늘의 리뷰 작성 후 종료.

## 3. Glossary

- **포도송이** — 사용자가 [새로운 포도송이 추가]로 시작한 하나의 주제(예: "달리기 1.5km", "독서 1챕터"). 15개들이 포도알 슬롯을 가지며, 정확히 하나의 "현재 걸음"을 가진다. 하루에 최대 1알까지만 채울 수 있다. 15알이 다 차면 졸업하여 루틴 체크리스트로 전환된다.
- **걸음** — 포도송이 안에서 사용자가 다음에 할 행동으로 입력한 한 줄. 완료(탭)되면 그날의 포도알로 기록된다.
- **포도알** — 걸음 하나를 완료했다는 기록의 최소 단위. 포도송이가 졸업하기 전까지만 적립되며, 탭 자체가 완료 인터랙션이다. 한 포도송이는 하루 1알로 제한된다.
- **오늘의 총 포도알 수** — 오늘 하루 동안 알을 받은 서로 다른 포도송이의 개수. FR-4의 제한상 활성 포도송이 개수를 넘지 않는다.
- **졸업** — 한 포도송이의 15알이 다 차서 루틴 체크리스트로 전환되는 사건. 이후 그 포도송이는 포도알을 적립하지 않는다.
- **루틴 체크리스트** — 졸업한 포도송이들의 목록. 다음 미완료 항목이 자동으로 강조 표시되며, 체크는 포도알/축하와 무관하다.
- **오늘의 리뷰** — 하루를 마무리할 때 작성하는, 잘한점·개선할 점·감사일기·확언 네 섹션으로 구성된 기록.

## 4. Features

### 4.1 포도송이와 걸음

**Description:** 사용자는 여러 개의 포도송이를 병렬로 키운다. 각 포도송이는 정확히 하나의 "현재 걸음" 칸만 가지며, 질문이나 재촉 없이 사용자가 준비됐을 때 채워 넣는 방식으로 진행된다. 앱은 별도의 온보딩/기상 트리거를 두지 않는다 — 첫 포도송이도 사용자가 직접 만든다. Realizes UJ-1.

**Functional Requirements:**

#### FR-1: 새 포도송이 생성

사용자는 [새로운 포도송이 추가] 버튼으로 새 포도송이를 만들 수 있다. 입력은 주제 이름 하나뿐이며, 세부 계획을 미리 쪼개도록 요구하지 않는다.

**Consequences (testable):**
- 새 포도송이 생성 직후 빈 "현재 걸음" 입력 칸이 뜬다(질문 문구 없이).
- 포도송이가 하나도 없는 최초 상태에서는 [새로운 포도송이 추가] 버튼만 있는 빈 화면을 보여준다.

#### FR-2: 포도송이당 단일 현재 걸음

각 포도송이는 언제나 정확히 하나의 "현재 걸음" 칸만 화면에 보여준다.

**Consequences (testable):**
- 이미 현재 걸음이 채워진 포도송이에 두 번째 걸음을 동시에 입력하는 UI 경로는 존재하지 않는다.

#### FR-3: 포도알 탭으로 걸음 완료

사용자는 현재 걸음의 포도알(다음 빈 슬롯)을 탭하여 완료 처리한다. 별도의 [완료] 버튼은 없다.

**Consequences (testable):**
- 탭 즉시 해당 포도송이에서 다음 빈 슬롯이 채워진다(단, FR-4의 하루 1알 제한 내에서).

#### FR-4: 포도송이당 하루 1알 제한

한 포도송이는 하루에 최대 1개의 포도알만 얻을 수 있다. 오늘 이미 알을 받은 포도송이는 현재 걸음 입력이 계속 가능하지만(예: 내일 할 걸음을 미리 적어두기), 탭해도 그날은 알이 추가되지 않는다. 이때 탭하면 부담 없는 짧은 안내("오늘 완료! 내일 만나요:D")가 잠깐 떴다 사라지며, 오류/경고 스타일은 쓰지 않는다.

**Consequences (testable):**
- 같은 포도송이에서 하루 두 번째 탭은 슬롯을 채우지 않는다.
- 다음 날이 되면 그 포도송이는 다시 알을 받을 수 있는 상태로 초기화된다.
- 오늘 치를 이미 받은 상태의 탭은 FR-7/FR-9/FR-10의 어떤 축하도 트리거하지 않는다.

`[ASSUMPTION: 안내 문구의 정확한 카피/애니메이션은 UX 단계에서 조정 가능하도록 열어둠]`

#### FR-5: 완료 후 조용한 대기 상태

걸음을 완료하면 FR-7의 축하 메시지가 뜨고, 현재 걸음 칸은 다음 입력을 묻는 질문 문구 없이 조용히 비워진 채로 대기한다. 사용자는 준비됐을 때 자유롭게 다음 걸음을 입력한다.

**Consequences (testable):**
- 완료 후 "다음은?" 류의 질문 텍스트나 강제 프롬프트가 뜨지 않는다.
- 포도송이를 그날 더 채우지 않아도 앱은 별도의 알림이나 재촉을 하지 않는다.

**Out of Scope:**
- 포도송이를 오늘만 "그만"하도록 명시적으로 종료시키는 버튼은 없다 — 그냥 비워두면 된다.

#### FR-6: 현재 걸음 수정/삭제

사용자는 현재 걸음 옆 오버플로(⋯) 버튼으로 [수정] 또는 [삭제]를 선택할 수 있다. [수정]은 걸음이 크다고 시스템이 먼저 단정하지 않는 중립적인 문구로 새 입력을 받아 현재 걸음을 교체한다. [삭제]는 현재 걸음을 비워 FR-5의 조용한 대기 상태로 되돌린다.

**Consequences (testable):**
- 수정/삭제된 걸음은 이전 걸음을 대체하며 별도로 기록에 남기지 않는다(포도알은 아직 적립되지 않은 상태).
- [삭제] 직후 카드는 걸음 완료 직후와 동일한 빈 입력 상태가 된다.

### 4.2 포도송이 진행률과 축하

**Description:** 포도송이의 진행 상황을 상시 노출하고, 행동할 때마다, 그리고 하루 총량이 의미 있는 기록을 세울 때마다 축하한다. 어제 총알 수 자체를 화면에 상시 표시하지는 않는다 — 비교는 축하 트리거로만 드러난다. Realizes UJ-1.

**Functional Requirements:**

#### FR-7: 탭마다 축하 메시지

포도알을 탭해 그날의 알을 받을 때마다 "어제보다 나은 오늘입니다!" 메시지가 표시된다.

**Consequences (testable):**
- FR-4에 의해 알이 늘지 않는 탭(오늘 치를 이미 받은 경우)에는 이 축하가 뜨지 않는다.

#### FR-8: 오늘의 총 포도알 수 계산

시스템은 오늘 하루 동안 알을 받은 서로 다른 포도송이의 개수를 오늘의 총 포도알 수로 집계한다. 화면에 상시 노출되는 숫자는 아니며, FR-9/FR-10의 축하 트리거를 판단하는 데만 쓰인다.

**Consequences (testable):**
- 같은 포도송이가 하루 안에 여러 번 집계되지 않는다(FR-4의 하루 1알 제한과 정합).
- 과거 날짜별 총량은 §5 Cross-Cutting NFRs의 날짜별 데이터 확정에 의존해 계속 조회 가능해야 한다.

#### FR-9: 어제 총합 돌파 축하

오늘의 총 포도알 수가 어제의 총 포도알 수를 처음으로 초과하는 순간, "🎉 어제를 넘었어요!" 축하가 별도로 표시된다.

**Consequences (testable):**
- 같은 날 이미 이 축하가 한 번 떴다면, 그날 다시 뜨지 않는다(하루 1회).

#### FR-10: 역대 최고 기록 축하

오늘의 총 포도알 수가 지금까지 기록된 하루 최고 총합과 같거나 이를 넘는 순간, 별도의 상위 축하(예: "🏆 역대 최고 기록이에요!")가 표시된다.

**Consequences (testable):**
- 같은 탭에서 FR-9와 FR-10 조건이 동시에 충족되면, FR-10(역대 최고 기록)만 표시하고 FR-9는 생략한다.
- 최고 기록 값은 이후 계속 갱신되어 저장된다.

#### FR-11: 포도송이별 진행률 상시 표시

각 포도송이는 자신의 진행률(N/15)을 화면에 항상 보여준다. 졸업 순간까지 숨기지 않는다.

**Consequences (testable):**
- 성장 중인 포도송이는 목록 어디에서 보든 N/15 형식의 숫자를 항상 렌더링한다(숨김/서프라이즈 상태 없음).

#### FR-12: 활성 포도송이 개수 요약 표시

화면은 아직 졸업하지 않은(성장 중인) 포도송이의 개수를 "N개의 포도송이 키우는 중" 형태로 보여준다.

**Consequences (testable):**
- 졸업한 포도송이는 이 개수에 포함되지 않는다.

---

### 4.3 루틴 졸업과 체크리스트

**Description:** 충분히 반복된 포도송이는 더 이상 결정을 요구하지 않는 루틴으로 전환된다. Realizes UJ-2.

**Functional Requirements:**

#### FR-13: 포도송이 완성 시 자동 졸업

한 포도송이의 15알이 가득 차면, 그 포도송이는 자동으로 루틴 체크리스트 항목으로 전환된다.

**Consequences (testable):**
- 졸업한 포도송이는 그 시점부터 포도알을 더 이상 적립하지 않는다.
- 졸업한 포도송이는 FR-12의 활성 개수에서 제외된다.

#### FR-14: 루틴 체크리스트 자동 순서 안내

루틴 체크리스트는 다음 미완료 항목을 강조 표시하여 사용자가 순서를 고민하지 않도록 한다.

**Consequences (testable):**
- 체크리스트의 미완료 항목 중 정확히 하나(다음 순서)가 시각적으로 구분되는 강조 스타일로 표시된다.

#### FR-15: 체크리스트 완료는 포도알/축하와 무관

루틴 체크리스트 항목을 체크해도 포도알이 적립되지 않고, FR-7/FR-9/FR-10의 어떤 축하도 트리거되지 않는다.

#### FR-16: 졸업한 항목의 재도전/삭제

사용자는 루틴 체크리스트의 각 항목에 대해 [다시 도전하기] 또는 [삭제하기]를 선택할 수 있다.

**Consequences (testable):**
- [다시 도전하기]를 선택하면 그 항목은 체크리스트에서 제거되고, 같은 이름의 새 포도송이(0/15)가 생성된다.
- [삭제하기]를 선택하면 그 항목은 체크리스트에서 완전히 제거되며 복구되지 않는다.

### 4.4 오늘의 리뷰

**Description:** 하루를 마무리하며 짧은 회고를 남긴다. Realizes UJ-1, UJ-2.

**Functional Requirements:**

#### FR-17: 오늘 마무리 액션

`[ASSUMPTION]` 사용자는 포도송이 상태와 무관하게 언제든 "오늘 마무리하기" 액션으로 하루를 종료하고 오늘의 리뷰 작성 화면으로 이동할 수 있다.

#### FR-18: 오늘의 리뷰 4개 섹션

오늘의 리뷰는 잘한점, 개선할 점, 감사일기, 확언 네 개의 입력 섹션으로 구성된다. `[ASSUMPTION: 네 섹션 모두 선택 입력이며, 비워두고 저장할 수 있다]`

`[NOTE FOR PM]` 감사일기·확언은 감정/다짐 위주 기록이라 원칙 7("감정이 아니라 행동을 기록한다")과 결이 다르다. 하루 중 포도알/체크리스트는 행동만 기록하고, 이 리뷰만 예외적으로 감정·성찰을 담는 구조로 의식적으로 남겨둔 것 — 사용자가 명시적으로 요청한 기능이라 그대로 유지한다.

#### FR-19: 리뷰 저장 시 하루 확정

오늘의 리뷰를 저장하면 그날의 걸음/포도알 데이터가 확정되고, 앱은 다음날을 위한 상태로 넘어간다.

**Feature-specific NFRs:**
- 리뷰 데이터는 날짜별로 구분되어 나중에 다시 열람 가능해야 한다.

## 5. Cross-Cutting NFRs

원 기획서(`handoff-prompt_1.md` §최종 지시)에 명시됐던 플랫폼/영속성 요구사항. FR과 달리 특정 기능이 아니라 앱 전체에 적용된다.

- **PWA 설치 가능성** — manifest + 적절한 meta 태그를 포함해 "홈 화면에 추가" 시 주소창 없는 전체화면(standalone)으로 실행되어야 한다.
- **로컬 영속성** — 모든 데이터(포도송이, 포도알, 날짜별 총합, 역대 최고 기록, 오늘의 리뷰)는 브라우저 localStorage에 저장된다. 서버 없음. "어제보다 나은 오늘" 비교는 이 영속성에 의존한다.
- **모바일 세로화면 우선** — 폰 화면 비율 기준으로 설계하며, 큰 탭 타깃과 한 손 조작을 지원한다.
- **단일 파일, 외부 의존성 없음** — 단일 HTML 파일 하나로 동작하며, 파일을 열면 외부 리소스 없이 즉시 돌아가야 한다.
- **날짜별 데이터 확정** — FR-19에 따라 하루 데이터가 날짜 키로 분리 저장되어야 "어제 대비"·"역대 최고" 비교와 리뷰 열람이 가능하다.

## 6. Non-Goals (Explicit)

- 로그인, 계정, 다중 사용자, 서버 동기화를 만들지 않는다.
- 최종 목표를 퍼센트/진도율로 보여주는 어떤 화면도 만들지 않는다.
- 포도송이 생성 시 세부 계획을 미리 전부 쪼개게 하는 입력 흐름을 만들지 않는다.
- 알림/푸시로 재촉하는 기능을 만들지 않는다(pull 방식만).
- 걸음 완료 후 "다음은?"을 묻는 대화형 프롬프트를 만들지 않는다 — 조용히 대기할 뿐이다.
- 한 포도송이가 하루에 2알 이상 받는 것을 허용하지 않는다.
- 어제 총 포도알 수를 화면에 상시(앰비언트) 표시하지 않는다 — 축하 트리거로만 드러난다.
- 개별 포도알 단위의 메모 기능은 만들지 않는다 — 회고는 하루 단위(오늘의 리뷰)로만 존재한다.
- 전역(모든 포도송이 합산) 누적 카운터는 만들지 않는다 — 진행률은 포도송이별로만 존재한다.
- 별도의 "기상 미세동작" 온보딩 기능을 만들지 않는다 — 첫 포도송이/걸음도 사용자가 다른 것과 동일하게 직접 정의한다.

## 7. MVP Scope

### 7.1 In Scope

- 포도송이 생성/성장 + 하루 1알 제한 (FR-1~FR-6)
- 탭 축하 + 어제 돌파/역대 최고 축하 + 진행률·개수 표시 (FR-7~FR-12)
- 루틴 졸업 + 체크리스트 + 재도전/삭제 (FR-13~FR-16)
- 오늘의 리뷰 4섹션 (FR-17~FR-19)
- Cross-Cutting NFRs: PWA 설치, localStorage 영속성, 모바일 세로 최적화, 단일 파일 (§5)

### 7.2 Out of Scope for MVP

- 여러 기기 간 동기화/백업.

## 8. Success Metrics

**Primary**
- **SM-1**: 제작자가 이 앱을 설치 후 최소 2주간 매일 열어본다. Validates FR-5, FR-7.
- **SM-2**: 첫 두 달 안에 최소 하나의 포도송이가 루틴으로 졸업한다(하루 1알 제한상 최소 15일 소요). Validates FR-13.

**Counter-metrics (do not optimize)**
- **SM-C1**: 포도송이 개수를 인위적으로 늘려 "키우는 중" 숫자만 부풀리는 행동은 성공으로 보지 않는다. Counterbalances SM-2.
